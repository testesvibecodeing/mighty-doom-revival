Patcher local

O cliente não sai do seu computador.

O patcher é parte essencial do projeto. Ele recebe a cópia local fornecida pelo usuário, configura o endpoint da instância escolhida e gera a saída localmente.

O projeto central não distribui o APK do jogo.Não existe mecanismo de download automático de APK de terceiros neste site.
  • entrada fornecida pelo próprio usuário
  • endereço do servidor informado pelo usuário
  • rebuild, alinhamento e assinatura locais
  • saída não enviada ao projeto central

Pacote configurado pelo administrador

Uma instância pode, opcionalmente, disponibilizar aos seus próprios usuários um APK já configurado para aquele servidor. Isso é uma decisão do administrador daquela instância — não uma distribuição oficial ou centralizada do projeto Revival.

O administrador que optar por hospedar um pacote configurado é responsável por avaliar permissões, licenças e legislação aplicável à sua jurisdição. O projeto central não busca, importa ou redistribui automaticamente APKs de terceiros.

Distribuição da instância

Transparente sobre o que cada servidor oferece.

O endpoint GET /revival/apk existe para informar se esta instância publicou um pacote configurado, incluindo metadados como tamanho e SHA-256.

A presença desse arquivo não muda o fluxo principal do projeto: qualquer usuário pode continuar usando sua própria cópia e executar o patcher localmente para o servidor que escolher.

FAQ

Perguntas sem linguagem ambígua.

O Revival descreve exatamente o que é central, o que é local e o que pertence à instância administrada pelo usuário.

Revival é oficial ou afiliado aos titulares do jogo?

Não. É um projeto comunitário, independente e não oficial. Não é afiliado, patrocinado ou endossado pela Bethesda, ZeniMax, Microsoft, id Software ou Alpha Dog Games.

O projeto central fornece o APK de Mighty DOOM?

Não. O fluxo principal exige que o usuário obtenha legitimamente sua própria cópia e execute o patcher local. O site não possui mecanismo de download automático a partir de repositórios de APK de terceiros.

Por que existe um botão de pacote/APK nesta página?

Porque cada servidor Revival pode ser administrado por uma pessoa diferente. O administrador da instância pode optar por hospedar um pacote já configurado para os usuários daquela própria instância, sob sua responsabilidade e conforme a legislação aplicável. Isso não é uma distribuição central do projeto.

Posso usar o patcher mesmo se a instância oferecer um pacote?

Sim. O patcher local continua sendo um fluxo independente: você fornece sua própria cópia e escolhe o endereço do servidor.

Onde meu progresso e as configurações ficam armazenados?

Na infraestrutura da instância escolhida. O Revival foi projetado para ser self-hosted; o administrador controla banco, configuração, domínio, eventos e demais dados do próprio servidor.

O nome Mighty DOOM é propriedade do projeto Revival?

Não. O nome e demais marcas pertencem aos seus respectivos titulares. O site usa o nome somente quando necessário para identificar, de forma descritiva, o cliente com o qual a infraestrutura busca interoperabilidade.
